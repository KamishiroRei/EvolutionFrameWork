# 知识管理

长期保留有明确来源和复用价值的内容。

- 用户明确要求持续遵循的目标、偏好、约束和协作方式，写清适用对象。
- 实际摸索、定位、纠错或指导后形成的经验，写清原因、成立条件及下次用法。
- 后续工作依赖的真实工具入口、数据约定和项目事实，写清所有者和变化后如何核对。

涉及行为限制和执行前提的知识，写清明确用户要求、已查证的业务规则或正常使用行为等依据，区分要求来源与实现现状。AI 自选的检查、等待和门禁是否必要，由这些依据判断，存在于代码或通过测试本身不构成保留理由。

全局 AGENT 承接通用工作规范。同一专业由一个主 SKILL 贯通目标、选型、常用技术做法和交付，建模、精修、修复等工作方式作为内部专业索引。常见任务在主正文连贯说通，专项技术与工具经验放在技能内部参考。按实际产物、责任和使用方式划分专业，界面制作、编译环境、引擎使用等独立能力仍可按需要串联。项目规则、业务事实与命令归项目。临时假设、进度与一次性选择归当前任务。动态判断依靠当时的用途和证据。

检查技能时，问它为后续工作提供了什么可复用的判断、知识或能力。职责重叠时将有效内容融入所属正文，局部方法放到参考，项目专属内容回到项目。通用提示、过时约束和多余转接随合并退出。模板和脚本按真实消费者保留。

修改时一并完成相交加载配置、索引、调用与引用，完成编辑即交付，禁止另行加载复验或全量链接核查。共同维护的内容有一个实际所有者，独立部署的副本按各自的使用条件维护。退役时核对文件身份及共享依赖，让旧入口和旧引用一起退出。

全量或定期检阅按[系统检阅方法](references/system-review.md)工作。日常任务优先完成当前目标，遇到值得复用的变化再更新所属正文。

用户启用的[审核监督](../agent-collaboration/SKILL.md#审核监督)按其完整流程观察成果并核实执行；本页负责其中经验回写的价值、归属与融合判断。方法修订是否改善后续制作，继续由实际成果反馈。
