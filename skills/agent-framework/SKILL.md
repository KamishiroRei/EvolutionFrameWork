# AgentFramework

从一两个代表性任务出发。确认使用者、最终成果、现有实现与重复遇到的专业问题，再选择内容的归属。

| 内容 | 所属位置 |
|---|---|
| 跨任务的交流、交付和工作约定 | 平台实际加载的全局或项目规则入口 |
| 有独立使用条件、专业判断和完整产出的能力 | 平台支持的技能入口及其正文 |
| 某种情形才用到的长说明、脚本与资源 | 所属技能的配套目录 |
| 业务事实、运行入口、构建命令与领域约定 | 项目自身的规则与文档 |
| 当前目标、在途操作和交接状态 | 当前任务的已有记录 |

优先复用现役能力。步骤多的任务可以由主控直接组织。若多个独立技能经常协作且存在稳定的选择和交接问题，才为它们设置调度入口。调度入口说明目标、何时取用哪个能力、依赖、交接和最终整合，执行技能各自拥有专业正文与产物。

每个技能用准确的名称和描述帮助发现，正文讲适用条件、关键判断、实际入口和结果。长资料按需链接。本仓库的 `skills/` 是分发结构；实际接入时，按平台支持的发现方式、目录和格式部署技能与配套资料。平台不支持技能机制时，将所需方法接入其支持的规则或工作资料。

迁移前查明规则范围与覆盖顺序、技能发现及格式、工具权限、角色能力、资源位置与调用方。按授权修改对应平台和项目的入口，并验证实际加载。共享正文由其所有者维护，独立副本各自保存和更新。用代表任务检查能否找到恰当技能并完成交付，再改变一个影响路线的输入，看能力选择是否随之调整。

任务较长或需要接手时，按需复用[任务交接模板](references/task-handoff.md)。系统的持续维护沿[知识管理](../knowledge-management/SKILL.md)。
