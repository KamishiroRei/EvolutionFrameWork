# Evolution-Agent 框架说明

Evolution-Agent 面向软件开发、修复、重构和跨会话交付。基本规则适用于整个项目，专业方法按任务取用。团队可以从主规则开始，再将长期使用的技能接入自己的项目。

## 内容归属

| 层级 | 负责什么 | 例子 |
|---|---|---|
| 全局或仓库 AGENT | 跨任务的沟通与工作规范 | 先说预期效果，查明实现后再报做法 |
| SKILL 与参考 | 有明确触发条件的专业方法 | 精简编程、规则检阅、跨会话协作 |
| 项目文档 | 当前项目的事实、契约与运行入口 | 实际数据格式、构建命令、部署边界 |
| 任务记录 | 当前进度、证据和接续位置 | 原始目标、产物链接、待确认事项 |

技能按专业职责划分。几个能力确实长期协作时，调度入口说明何时使用哪个能力及怎样交接。技能可以独立使用，跨宿主部署按实际加载路径和副本归属维护。 [AgentFramework](../.agents/skills/agent-framework/SKILL.md)

## 从需求到交付

以“导出超时后重试，别生成两份文件”为例。首次回复表达的是可观察结果。同一次导出可以安全重试，最终只交付一份有效文件。然后追查正常导出、超时和重试各自的实际入口。

假设调查发现文件已经保存，但完成回执丢失，而且系统已有可查询的导出任务 ID。制作表就应写明复用任务 ID 查询结果，在实际完成位置接回原产物，并核对回执丢失后的重试。这个做法也要走一遍正常导出，确认已有路径和产物仍符合约定。

| 顺序 | 根据实际发现安排工作 | 可核对的结果 |
|---|---|---|
| 1 | 把重试接到原任务的状态查询 | 原任务完成后可取回既有产物 |
| 2 | 用一次正常导出和一次回执丢失场景检查 | 两条路径都返回有效结果，每次导出只有一份文件 |
| 3 | 记录实际改动与观察范围 | 接手者能找到正式产物、验证依据与未决事项 |

当任务事实不同，方案随之改变。新增幂等机制、重试分支或兼容层应有实际输入和职责依据。用户需要裁定行为时，说明有何不同及其后果。 [精简编程](../.agents/skills/lean-coding/SKILL.md)

## 工作留痕与接续

长任务把有用信息留在已有的 Issue、任务文档或交接记录。需要的时候记录原始目标、有效调整、关键依据、正式产物、验证范围和下一动作。在途或结果未知的操作记录可查询的身份，接手时先查状态。共享资源同时说明当前写入归属。 [任务交接模板](../.agents/skills/agent-framework/references/task-handoff.md)

构建、测试、实际运行、独立审核和用户接受各自有不同依据。交付时分别按真实完成情况说明，证据指向相关文件、版本、日志或可观察入口。安排独立审核时，审核者以原始要求和已认可的设计观察完整成果。 [协作与独立审核](../.agents/skills/agent-collaboration/SKILL.md)

## 规则怎样迭代

发现执行偏差时，先用原始请求和当时已有资料回放。找出问题发生在理解、探查、方案选择还是交付。修正最早诱发偏差的规则或读取入口，再用同类但不同的场景检查新规则是否仍能做出合理判断。

长期保存明确的用户要求、经实际摸索的经验和后续工作依赖的正式入口。定期检阅从实际加载链开始，合并重复职责，核对调用方，按项目和宿主划分归属。 [知识管理与系统检阅](../.agents/skills/knowledge-management/SKILL.md)
