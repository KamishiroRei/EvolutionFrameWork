# Git 交付

以项目约定的交付分支为准。新仓库通常从 `main` 开始。动手前核对仓库身份、当前工作区、待交付范围与远端。多人写同一仓库时明确整合方和各自文件归属。

按实际改动暂存和提交。提交前看待提交差异，确认内容属于任务和当前仓库，公开交付只纳入获准公开的资料。分支上的有效成果用可追溯的提交承接，临时材料按其归属处理。

推送前核对远端主线的变化。按项目约定整合差异并处理实际冲突，使用正常推送。共享历史重写、删除远端引用与发布范围按用户授权执行。结果未知时先查远端状态。提交、推送和发布完成后，回读实际分支与提交。

检查和构建以项目要求和本次改动为依据。Git 操作沿正常交付路径完成。
