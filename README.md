# EvolutionFrameWork

注重自我迭代能力与高效沟通的通用方法论工作流仓库，面向专业化开发。它提供跨任务工作规则和可按需选用的专业技能，帮助使用者从理解需求、调查实现到交付、留痕和迭代，形成可接续的工作方式。

| 工作重点 | 方法 |
|---|---|
| 高效沟通 | 先简述核心效果，探查后说明依据、做法和交付。追加需求并入同一份制作表，在已有授权内持续推进。 |
| 准确理解 | 把要求放进同一个正常使用场景，对照不同解释会改变什么、原有有效行为能否继续成立。 |
| 精简实现 | 沿真实调用链，按实际输入和契约决定必要检查。新增兜底或兼容分支须有依据。 |
| 准确自我迭代 | 从真实错例回放，找最早诱发偏差的规则或入口，用同类场景复核，保留稳定可复用的修正。 |
| 可接续的工作留痕 | 复用现有任务记录，保存原始目标、关键依据、实际产物和下一动作。长期知识与临时进度各有归属。 |

## 接入自己的工作环境

本仓库以 [AGENTS.md](AGENTS.md) 分发通用工作规则，以 [skills/](skills/) 分发技能正文和配套资料。目录结构用于组织与分发。使用时将所需内容接入实际平台支持的入口，并结合平台和项目确认：

1. **规则范围与覆盖**：查明平台支持哪些规则入口、适用范围及覆盖顺序。将需要的内容接入合适的全局或项目入口。已有规则时，合并有效条款并处理冲突。
2. **技能发现与格式**：查明平台是否支持技能发现、所需目录和文件格式。选用需要的技能，连同引用的参考资料一起接入。不支持技能机制时，可将相关方法融入平台支持的规则或工作资料。
3. **工具与权限**：按实际工具、文件访问和操作权限调整执行入口，保留方法所需的依据和验证，不假定其他环境具有相同能力。
4. **角色映射**：根据平台能力和任务需要安排执行、整合、专业执笔或独立审核，明确授权和交接。没有相应角色时，由实际负责人承担对应职责。
5. **验证加载**：检查规则与技能能否被发现、引用能否访问，再用代表性任务观察是否按预期使用。文件已复制、平台已加载和实际行为已验证应分别确认。

项目自身的业务事实、构建命令和交付约定仍由项目维护。按需要选择规则与技能，明确正式版本的所有者及副本的更新方式。

| 技能 | 何时使用 |
|---|---|
| [精简编程](skills/lean-coding/SKILL.md) | 修复或修改实现，审查兜底、兼容分支与检查是否有依据 |
| [知识管理](skills/knowledge-management/SKILL.md) | 判断知识的证据与复用价值，或检阅和精简规则体系 |
| [AgentFramework](skills/agent-framework/SKILL.md) | 组织或迁移工作规则、专业技能及其实际加载入口 |
| [协作与独立审核](skills/agent-collaboration/SKILL.md) | 已授权的任务分工、跨会话接续或独立审核 |
| [Git 交付](skills/git-workflow/SKILL.md) | 提交、整合、推送或承接其他执行者的改动 |

## 一次沟通怎样推进

以“合并两个快捷动作，整理剩余键位”为例。先表达实际效果：合并后操作仍要连贯，界面提示要与实际按键一致。随后查绑定和提示的来源，确认合并后留下了空位，以及哪些入口还在使用原按键。

有了依据，再把重排绑定、更新提示和核对实际动作放进一份有序制作表。用户追加一项操作时，按依赖把它接入原表。简单任务可以用一句话说明目标和做法。

框架分层、实际工作例子、留痕字段与迭代方法见[框架说明](docs/framework.md)。许可证见 [MIT License](LICENSE)。
